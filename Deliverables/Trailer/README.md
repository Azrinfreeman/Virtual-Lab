# BioNutri-MM gameplay trailer

Primary deliverable: `BioNutri-MM_Gameplay_Trailer_60s.mp4` (1920×1080, 30 fps, 60 seconds, H.264 video / AAC stereo audio).

## Contents

| Time | Content |
|---|---|
| 00–04 | 3D carbohydrate laboratory overview |
| 04–09 | Eight-activity selection menu |
| 09–20 | Measuring-cylinder and test-tube transfer animations |
| 20–29 | Test-tube observation and water-bath sequences |
| 29–36 | Vitamin C apparatus and syringe sequences |
| 36–38 | Human digestive-system view |
| 38–43 | Healthy Plate food placement |
| 43–49 | Offline chatbot question and sample answer |
| 49–55 | Carbohydrate quiz interaction |
| 55–60 | Closing laboratory view and BioNutri-MM branding |

Footage is staged from actual project scenes and authored gameplay animations in Unity Play Mode, with a recording-only helper. It is an edited showcase rather than an uninterrupted manual play session. Lab animation states are invoked through the same Animator states used by the experiment controllers. Waits and setup screens are omitted; the edit discloses shortened timings. No generated laboratory images, fabricated online scores, or live AI responses are presented.

The score is an original synthesized instrumental generated by the export recipe. It does not use the project's third-party music. Gameplay audio and narration are not included.

## Offline chatbot

The existing `OpenAI.ChatGPT` component has an **Offline Demo Mode** Inspector setting, default OFF. For a local demonstration, enable it in Play Mode and open the chat panel. It answers a small set of Malay questions about amylase, vitamin C/DCPIP, and the Healthy Malaysian Plate. Unknown questions explicitly explain that the demo is offline.

The demo uses local fixed responses, not a ChatGPT account or provider API. No API key or session token is required. The trailer labels this mode both in the chat and in the edit. Normal endpoint/session checks remain in place when demo mode is OFF. No normal scene or prefab is saved with demo mode enabled.

## Reproduction

1. Open the Unity project, check that the active scene has no unsaved changes, and enter Play Mode.
2. Invoke `TrailerDirector.Begin()` through Unity MCP or an editor script. The recording helper is under `#if UNITY_EDITOR` and is never attached to saved scenes. In an editor session where Start has not yet run, `FindFirstObjectByType<TrailerDirector>().StartCoroutine("Start")` starts it explicitly; a guard prevents duplicate runs.
3. The helper writes 1,800 numbered JPEG frames to ignored `Temp/Trailer/frames`. `TrailerDirector.Status` reports progress. It restores its capture-rate and plate-completion preferences on completion and stops Play Mode.
4. `TrailerDirector.PatchShots()` replaces the vitamin-C segment and digestive insert. `TrailerDirector.PatchEnding()` records the final quiz/lab sections independently. These helpers are useful for replacing takes without re-recording the full minute.
5. Set the `FFMPEG` environment variable to a local FFmpeg encoder supporting libx264, AAC and drawtext, then run `node Tools/Trailer/export.mjs` from the project root.
6. The recipe writes the video, `thumbnail.jpg`, `original-score.wav`, caption files, and `edit-filter.txt`. Captions are placed in a dedicated lower band so they do not cover lesson instructions. The existing logo is overlaid only during the closing shot.

Raw frames are temporary and can be cleared by Unity; keep a separate archive if future re-editing without recapture is required. The final video and edit recipe live outside Temp. No encoder binary was installed or copied into the project.

## Verification and limitations

- The full recorded sequence contains 1,800 frames at 30 fps.
- Final MP4 decode completed without errors: 1,800 frames, 60.000000 seconds, zero duplicated/dropped frames reported by the decoder. Output size is approximately 19.2 MB.
- Final stereo mix measured -22.1 dB mean and -6.1 dB peak, with no peak clipping. Captions, offline-demo disclosure, and the logo ending were inspected in frames extracted from the final MP4.
- Offline-answer checks passed for three supported and three fallback/empty question cases; recording also showed the actual question and reply in the chat UI.
- Scene/prefab search found no saved `offlineDemoMode: 1` setting.
- Reviewed rendered frames across the full timeline and close views of the lab, digestive system, plate, and chat. Replaced a vitamin-C take with an obstructing introduction and replaced ending takes affected by a persistent chat panel.
- Existing QuickOutline mesh-readability errors occurred on some apparatus models during runtime capture. Model import settings were not changed as part of trailer production.
- The helper temporarily suppresses online score-loading/saving components for recording and never uses a real student account. The live PHP backend remains unconfigured by this work.
- No deployment, upload, publication, credential rotation, or account changes were performed.

The saved editor scene is restored to StartMenu after recording. Use the MP4 as the shareable deliverable; the other files are production sources.
